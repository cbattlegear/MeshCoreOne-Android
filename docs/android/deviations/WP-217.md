# WP-217 simulator and demo-mode adaptations

Reference: `db14559b39d32322b06477c6ae676112f583db50`.
Owner: `services-porter`. The original seed implementation was an external
contribution prepared without a controller receipt. The #396 production-composition
follow-up is authored under the WP-217 session reservation; it does not establish
whole-WP dependency acceptance or authorize a dependency unlock. The original
adaptations below are retained as historical context where still applicable.

`DemoModeManager` and `DemoInlineImageSeeder` come from the app target. Their
logic lives in pure JVM services behind small ports (A-05), with Android
composition supplied by the production app.

## A-01: shape

- **Provider:** the Swift `MockDataProvider` enum and its `+Feature` extensions
  become a Kotlin `object` plus extension functions and properties, one file per
  Swift file. Swift visibility is kept: `public` members are public and `internal`
  ones are internal.
- **Build file:** `core/services/build.gradle.kts` is byte-identical to the
  WP-214 branch's shared verify-stage hook, so it merges cleanly with the other
  open PRs. That is why its second header names WP-212.
- **Explicit `now`:** each Swift computed static that reads `Date()` (`contacts`,
  `channels`, `messages(for:)`, `channelMessages(for:)`, `nodeStatusSnapshots`,
  `rxLogEntries`, `messageRepeats(for:)`, `simulatorDevice`) becomes a function that
  takes `now: Instant`. `SimulatorConnectionMode` reads its injected `Clock` once
  per seed pass. Swift instead calls `Date()` in every builder, microseconds apart.
- **Tuples:** the `(messageID, summary)` and link-preview tuples become the
  `ReactedMessage` and `LinkPreviewSeed` data classes. The snapshot batch result
  becomes `NodeStatusSnapshotInsertResult`.
- **Traps:** the Swift conversions that trap are `UInt32(date.timeIntervalSince1970)`,
  `UInt32` subtraction and `UInt16(Int)`. Here they fail fast with
  `IllegalArgumentException` and never wrap.
- **Logging:** messages go to `java.util.logging` with the same text.
  `PersistentLogger` belongs to WP-212.

## A-02: determinism

The seed is a pure function of `now`. Every row except the snapshot ids matches
the frozen Swift seed byte for byte at two pinned instants (see Evidence).

- **Snapshot ids:** Swift gives each `NodeStatusSnapshotDTO` a random `UUID()`.
  Here each id is a name-based UUID of the row's store key (node key plus
  millisecond). A fixed clock gives fixed ids, and rows seeded at different
  instants never share an id. `core:data` inserts snapshots by primary key with
  `ABORT` and dedups backup rows by that same key. An index-derived id would
  therefore make a later restore abort on an id clash; review finding 1.
- **Reaction `receivedAt`:** Swift's `ReactionDTO` defaults it to `Date()`. Here it
  is the pass's `now`.

## A-03: concurrency

- **State:** `@MainActor` state becomes lock-confined state. No lock is held
  across a suspension.
- **Seed passes:** `seedDataStore` runs one pass at a time under a coroutine
  `Mutex`. On the Swift main actor, two passes can interleave at `await` points.
  The RX-log and snapshot steps check and then insert, so two concurrent connects
  could insert the RX fixtures twice.
- **Cancellation:** `connect()` in Swift sleeps with `try? await Task.sleep`, which
  swallows cancellation and connects anyway. Here cancellation propagates and the
  mode stays disconnected. The 200 ms delay is injectable, and tests use zero.
  Store failures and `CancellationException` from the store propagate unchanged.
- **Demo-mode flags:** every assignment writes through to defaults, like Swift's
  `didSet` (even when the value is unchanged). A serialized, suspendable write
  publishes to `StateFlow<DemoModeState>` only after the defaults store confirms
  success. `unlock()` commits both keys in one DataStore edit and then publishes
  once. A failed or cancelled write does not display success; cancellation racing
  a completed durable edit cannot guarantee rollback, and retry is safe.

## A-04: transport

`SimulatorMockTransport` implements `MeshTransport` directly. It doesn't reuse
the protocol module's `MockTransport`, which behaves differently in two ways.
First, a send while disconnected fails with `MeshTransportError.NotConnected`, as
in Swift, where `MockTransport` throws `MockTransportException`. Second, the
received stream is created once and finished by the first `disconnect()`. A later
`connect()` doesn't reopen it, as in Swift. The transport never emits data and
never touches a radio, socket or file.

The production simulator graph deliberately does not start the physical
`SessionCore` handshake. Its placeholder transport remains disconnected:
simulator readiness is represented by the runtime's device state, not by a
fabricated radio connection or a successful packet delivery. Generation teardown
still owns and disconnects the placeholder.

## A-06: offline fixture boundary and remaining scope

Only the fixed simulator radio/message/URL identities can use the bundled link
preview and image, and the message-owned preview bytes and metadata are checked
before use. The decoded demo image has a separate cache key, so a later ordinary
message using the same URL cannot inherit fixture bytes. A missing or altered
fixture fails without falling back to HTTP. Ordinary messages retain the existing
malware and URL-safety checks. Simulator
chat suppresses automatic remote preview fetching and forces coordinate thumbnails
to the offline renderer; this is not a claim that every possible simulator UI
action is network-free. The broader link-preview work remains tracked by #397.

The composed graph and its new integration tests have not yet been verified on
this candidate. In particular, merged prerequisite repairs do not establish
whole-WP acceptance, and API 31/37 device runtime evidence remains outstanding.

## Test adaptations

- **Store:** a fake with fault injection replaces the SwiftData in-memory
  container. The fake keeps the Swift semantics the seed depends on: id upserts,
  and `saveMessage` (`Message(dto:)`) dropping the preview blobs and resetting
  `linkPreviewFetched` while keeping the URL, title and summary. It also keeps
  insert-only RX rows and parent-checked repeats.
- **Defaults:** each `DemoModeManagerTests` case gets a fresh
  `InMemoryDemoModeDefaults`, the stand-in for `UserDefaults(suiteName:)`. The
  `shared` case installs the process store first.
- **Clock:** the re-seed cases advance a settable clock between passes, as a
  reconnect would. No test sleeps.
- **Swift `UserDefaults.bool(forKey:)`:** Swift also coerces stored strings and
  numbers to `Bool`. The port carries only booleans.
