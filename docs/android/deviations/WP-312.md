# WP-312 deviations and remaining provider boundary

## Exact provider decision

The user explicitly selected MapLibre Native `org.maplibre.gl:android-sdk:13.6.1`
with the OpenFreeMap Liberty style at
`https://tiles.openfreemap.org/styles/liberty`. This resolves ADR-002 for the base map and its MapLibre-managed offline
regions. The app visibly presents links for OpenFreeMap,
OpenMapTiles and OpenStreetMap attribution. No account, API key, Google service
or new Android permission is used.

OpenFreeMap does not provide an admitted satellite layer and no approved
topographic style was selected. Both controls remain visible but disabled; they
do not fall back to the standard layer or claim success.

## Native adaptations

- A lifecycle-bound MapLibre `MapView` is hosted by Compose and receives real
  process-store contacts and discovered nodes for the current radio.
- GeoJSON sources use stable DTO IDs, separate clusterable/fixed partitions,
  point and line layers, cluster expansion, labels, selection, type/favorite/
  discovered filters and an accessible node-list alternative.
- Camera and filter preferences survive process recreation. A map deep link is
  retained as a nonclustered message/location marker and updates the camera.
- `MapSnapshotter` is integrated through the existing bounded snapshot store.
  Offline snapshot requests return unavailable rather than silently using the
  network.
- `OfflineManager` region create/progress/pause/resume/delete behavior is
  process-owned and exposed through the map UI for the currently visible base
  map bounds, including cancellation cleanup and persisted metadata.
- The OpenFreeMap project explicitly documents its public instance as free
  with no request limits and publishes weekly MBTiles/PMTiles/Btrfs planet
  snapshots for self-hosting. The Android app uses MapLibre OfflineManager
  regions rather than pretending MapLibre Native can mount an arbitrary
  MBTiles file directly.

## Deliberate layer exclusions

OpenFreeMap does not host satellite, raster, elevation or topographic products.
Satellite and topographic controls therefore remain visible and unavailable,
and offline downloads offer the base layer only. Direct local MBTiles mounting
would require another admitted renderer/protocol and is not claimed by this WP.

MapLibre 13.6.1's 64-bit `arm64-v8a` and `x86_64` libraries have 16 KiB
`PT_LOAD` alignment. Its 32-bit libraries are 4 KiB-only, so those two MapLibre
libraries are excluded while the app retains its existing 32-bit non-map native
support. Map rendering, snapshots and offline regions fail closed as unavailable
on a 32-bit process. Static APK alignment is verified; no physical 16 KiB device
execution is claimed.

preserves scalable text and native touch targets without changing actions,
filters or provider availability. Wrapped rows have vertical separation.

This accepts only the bounded font200 regression, not physical TalkBack,
radio/offline behavior or full WP-312 completion.
