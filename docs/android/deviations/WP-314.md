# WP-314: trace path, node discovery, and tools home

Reference: `db14559b39d32322b06477c6ae676112f583db50`.

## Native adaptations

- SwiftUI navigation stacks and regular-width columns use the existing Navigation 3 adaptive
  list/detail shell. The feature receives the selected tool as a typed value and does not own a
  second navigation stack.
- `TracePathViewModel` and `NodeDiscoveryViewModel` remain feature state holders with injected
  clocks and live providers. The app adapter reads the current `RadioSessionContainer` for every
  operation and the trace listener re-subscribes whenever `AppState.servicesVersion` changes.
- Trace maps use the shared WP-312 MapLibre surface and provider catalog. A result without at least
  two located hops shows an explicit unavailable state rather than drawing a fabricated route.
  Map accessibility text includes every located hop and numeric SNR; line quality uses the source
  `SNRQuality` boundaries.
- Recent hop keys use private Android preferences with the source key prefix and preserve
  most-recent-first order. No permission or network dependency was added.
- Source haptics are represented by state counters for the host accessibility/haptic layer; this WP
  does not claim physical-device haptic verification.

## Preserved behavior

- Trace tags and radio identity correlate responses; reconnects replace listeners.
- Partial, timeout, send-failed, cancellation, batch, and save outcomes remain distinct.
- Path edits invalidate stale results, saved-path identity is retained, and deleting an active saved
  path clears that identity.
- Discovery filters repeaters/sensors by the firmware masks, keeps contact-added state, sorts by SNR
  or localized name, and stops a superseded scan by generation.
- Radio commands run only from explicit Run Trace, Scan, Add, or Stop actions.

### TS-11 running-edit safety adaptation

The pinned Swift holder clears `pendingPathHash` on edits but leaves its trace tag live.
The newly reachable Android reorder/clear actions exposed that a late response could then
publish using an empty path and the edited hash width. Android retains editing during a
trace, but a result-invalidating edit now retires the active single/batch execution using
the existing cancel path. Already completed history is retained; no radio command is sent
by the edit. The busy state is cleared and the normal explicit Run Trace action starts a
new execution for the edited route.

A runner generation fences suspended send completions, saved-path lookup and inter-trace
continuations from later executions. Timers and pending response correlation are retired
before the edit; an already accepted history write may finish but cannot restore a cleared
saved-path reference. Refresh eligibility binds the full radio/path key and a separate
path-selection revision (not the runner generation),
so clear/reselect cannot revive an earlier selection even when its UUID matches. Mounted
move/remove callbacks also check the captured hop UUID at their rendered index before editing;
a retained callback cannot mutate or cancel the different hop now occupying that index.
The accessibility action explicitly captures that rendered callback rather than relying
on the button's mutable Clickable delegate, which Compose rebinds when a keyed row moves.

failure), late responses, waiting timeouts, partial batch history, a newer run, and suspended

Auto Return uses the same invalidation boundary only when it changes the effective wire

Both holder and mounted-switch regressions reject the
old response and then complete a newly requested trace on the changed route. Starting or

history refresh; a held-fetch regression preserves visible runs and previous-run comparison.

commits, so an older snapshot held after the actual store read cannot overwrite a newer
