# WP-314: trace path, node discovery, and tools home

Reference: `db14559b39d32322b06477c6ae676112f583db50`.

## Native adaptations

- SwiftUI navigation stacks and regular-width columns use the existing Navigation 3 adaptive
  list/detail shell. The feature receives the selected tool as a typed value and does not own a
  second navigation stack.
- `TracePathViewModel` and `NodeDiscoveryViewModel` remain feature state holders with injected
  clocks and live providers. The app adapter reads the current `RadioSessionContainer` for every
  operation and the trace listener re-subscribes whenever `AppState.servicesVersion` changes.
- Trace maps use the shared WP-312 MapLibre surface and provider catalog. A result without at least
  two located hops shows an explicit unavailable state rather than drawing a fabricated route.
  Map accessibility text includes every located hop and numeric SNR; line quality uses the source
  `SNRQuality` boundaries.
- Recent hop keys use private Android preferences with the source key prefix and preserve
  most-recent-first order. No permission or network dependency was added.
- Source haptics are represented by state counters for the host accessibility/haptic layer; this WP
  does not claim physical-device haptic verification.

## Preserved behavior

- Trace tags and radio identity correlate responses; reconnects replace listeners.
- Partial, timeout, send-failed, cancellation, batch, and save outcomes remain distinct.
- Path edits invalidate stale results, saved-path identity is retained, and deleting an active saved
  path clears that identity.
- Discovery filters repeaters/sensors by the firmware masks, keeps contact-added state, sorts by SNR
  or localized name, and stops a superseded scan by generation.
- Radio commands run only from explicit Run Trace, Scan, Add, or Stop actions.
