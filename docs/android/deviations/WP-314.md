# WP-314: trace path, node discovery, and tools home

Reference: `db14559b39d32322b06477c6ae676112f583db50`.

## Native adaptations

- SwiftUI navigation stacks and regular-width columns use the existing Navigation 3 adaptive
  list/detail shell. The feature receives the selected tool as a typed value and does not own a
  second navigation stack.
- `TracePathViewModel` and `NodeDiscoveryViewModel` remain feature state holders with injected
  clocks and live providers. The app adapter reads the current `RadioSessionContainer` for every
  operation and the trace listener re-subscribes whenever `AppState.servicesVersion` changes.
- Trace maps use the shared WP-312 MapLibre surface and provider catalog. A result without at least
  two located hops shows an explicit unavailable state rather than drawing a fabricated route.
  Map accessibility text includes every located hop and numeric SNR; line quality uses the source
  `SNRQuality` boundaries.
- Recent hop keys use private Android preferences with the source key prefix and preserve
  most-recent-first order. No permission or network dependency was added.
- Source haptics are represented by state counters for the host accessibility/haptic layer; this WP
  does not claim physical-device haptic verification.

## Preserved behavior

- Trace tags and radio identity correlate responses; reconnects replace listeners.
- Partial, timeout, send-failed, cancellation, batch, and save outcomes remain distinct.
- Path edits invalidate stale results, saved-path identity is retained, and deleting an active saved
  path clears that identity.
- Discovery filters repeaters/sensors by the firmware masks, keeps contact-added state, sorts by SNR
  or localized name, and stops a superseded scan by generation.
- Radio commands run only from explicit Run Trace, Scan, Add, or Stop actions.

## Evidence limits

### TS-08 batch-results repair

The mounted list result card now consumes batch progress/completion, successful-only RTT
and per-hop SNR aggregates, and the most recent successful hop SNR during execution.
Progress is visible before the first response. Cancellation retains partial results,
counts and aggregates without a running spinner or a false completion announcement.
Path edits invalidate the batch presentation alongside the source's existing `result`
invalidation. Retained completed results, aggregate computation and same-path save/history
semantics are unchanged; cancellation alone does not invalidate presentation. If an active
batch receives another response after an edit, its individual result follows the source
behavior, but the result card does not apply retained batch SNR statistics to that route.
Existing localized strings supply visible and accessibility descriptions; RTT accessibility
formatting retains Long values instead of narrowing to Int.

### TS-09 code/paste entry repair

The trace list exposes an Add Hop code-entry panel using existing Material buttons, text input,
theme roles and localized path-edit strings. This is an inline native adaptation of the pinned
`AddHopPickerView` bulk workflow, not a second picker/navigation stack. Existing repeater buttons
remain available. Clipboard reads occur only after the explicit Paste action; blank clipboard
text leaves the draft unchanged. Comma-containing edits call the existing `adoptHashSize` before
previewing, preserving the firmware gate and the same-width no-op. Preview and submission use
the existing `classifyCodes` / `addCodes` APIs, not a copied parser.
Every Paste action clears prior outcome/announcement feedback, including empty or whitespace-only
clipboard no-ops, without changing an existing draft, path or hash width for those no-ops.

Per-code valid, duplicate, missing, invalid-format and capacity outcomes remain textual and
localized. Only resolvable new codes enable submission; submission clears the draft and retains
typed error categories for a polite accessibility announcement. Width changes and successful
additions retain the existing result/saved-path invalidation rules; opening the panel alone
does not edit the path. No radio command is sent by code entry.
After actual additions, the same polite live region announces the pinned picker's localized
next-append-hop banner. Its position is captured at submission and is absent for duplicates,
empty input and other no-add outcomes; mixed error feedback remains alongside it.
Code-entry state now lives outside the lazy item, and its explicit Bundle saver retains the
draft and each typed outcome category. Scrolling the item out of composition does not lose
partial-add feedback or reapply inference over an explicit width choice. After actual Activity
saved-state restoration, a lifecycle effect restores the saved selected override, not a new
inference from draft text, before exposing its preview. The selected mode is captured from the
live holder when saved, preserving deliberate manual choices and mixed/invalid drafts too.
Inference and restoration share the same firmware-gated, same-mode-no-op adoption helper.
This is native draft restoration, not persistence or restoration of the holder's trace
execution/history.
