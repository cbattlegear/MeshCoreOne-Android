# WP-401 notification platform deviations

Reference: `db14559b39d32322b06477c6ae676112f583db50`. Integrated base:
`2fc6cb6f59f49be94f033fdad32100c3fc5db055`.

## Android notification model

Swift notification categories map to Android 8+ notification channels. Audible and silent variants are
separate because Android owns sound at the channel level. Message categories use `MessagingStyle` and
long-lived conversation shortcuts; other categories use big text. Lock-screen public versions expose only
the app and generic category text.

The existing onboarding/settings flow remains the sole owner of `POST_NOTIFICATIONS` prompting. The
delivery adapter reports the current authorization state and never launches permission UI. Denial or
platform posting failure is a typed notification result and never blocks mesh messaging.

## Actions and process lifetime

Android notification content taps launch the package's launcher Activity directly with an immutable
activity `PendingIntent`; the typed notification payload retains the notification-ID action URI and radio,
contact/session/channel/message identity. Direct reply and mark-read remain explicit, non-exported
broadcast actions. Only the inline-reply `PendingIntent` is mutable. Action extras contain typed
identifiers but no title, body or reply text.

A process-owned queue retains at most 32 cold-start actions and retries for 15 seconds while application
and radio-session state becomes ready. Session creation explicitly retriggers draining. Responses keep the
payload's original radio identity; WP-215 therefore rejects stale-radio transmission while mark-read
targets the payload's own persisted rows.

## Notification content tap repair (#503)

The notification body no longer targets `NotificationActionReceiver`, so opening a notification does not
depend on a receiver starting an Activity and avoids Android 12+ notification-trampoline behavior. The
launcher receives the same `OPEN` action, notification-ID URI, and typed payload extras. The separate
WP-302 Activity-entry adapter enqueues this payload through the existing process queue for current
session/generation-aware navigation; until that producer's Activity hook is integrated, this WP-401
change verifies the platform delivery half only.

## Verification boundary

Robolectric exercises notification construction and action plumbing on the host JVM, including the direct
activity `PendingIntent` at API 31 and 37. Android instrumented test sources compile into an APK, but no
emulator/device, launcher badge, OEM channel UI, physical radio, signing or release verification is claimed.
