# WP-403 deviations

## Native platform adaptation

The frozen `MC1RadioControl` runs outside the iOS app and only opens MeshCore One because that
widget process has no radio access. Android supplies two optional surfaces:

- the Glance widget remains a redacted status glance; tapping its body opens the app, while its
  explicit **Connect** action requests the process connection owner;
- the Quick Settings tile is an explicit system user action and requests the same owner.

Neither component constructs a transport, `ConnectionManager`, session container, service graph or
foreground service. `MeshCoreApplication` installs the process bridge before asynchronous
`AppContainer` construction, and the bridge waits for that existing owner with a bounded timeout.
Repeated widget/tile taps are serialized; an already active owner is not asked to reconnect.

## Storage and privacy

The widget cache contains only connection phase, saved-device availability, reconnecting and
permission-needed booleans. It contains no radio name, public key, address, message, room, channel
or contact data. Credential-protected cache reads/writes are suppressed before first unlock, where
the system surfaces show a disconnected, content-free state.

Glance receives one generated `64 x 64` ARGB bitmap per render (16 KiB maximum). The tile uses a
vector resource. No image, identity or message cache was added.

## Platform behavior

API 31-37 use the same typed request/status contract. API 34+ uses the `PendingIntent` Quick
Settings launch API; API 31-33 uses the only platform overload available there. Permission,
pre-unlock, owner-startup timeout, background refusal and no-saved-radio outcomes remain typed and
open the app only where user recovery is required. Optional widget/tile failures do not gate mesh
messaging, persistence or navigation.

## Unverified gates

No physical radio, launcher, OEM background-policy, emulator, iOS, screenshot or accessibility
service run is claimed. JVM/Robolectric tests cover registration, API-range policy, redaction,
pre-unlock, permission/background outcomes, reconnect serialization and bitmap bounds.

## Issue #740: radio metrics on the home screen

The expanded home-screen widget shows optional battery percentage, live trailing-minute RX
packets and aggregate unread messages. As on iOS, the values come from the connection's battery
monitor and parsed RX arrivals and from persisted unread data. Android reuses the 60-second
RX Log rate; it never reconstructs that rate from stored packets. Room invalidation refreshes
unread counts using the existing mute, block and mention rules. Unknown counts and missing or
expired battery readings are omitted; a measured zero is displayed.

Unlike the upstream Live Activity, this is a home-screen-only surface. The radio name and
all identifying or message content remain redacted. API 36+ opts the widget out of the system
lock-screen picker; rendering also requires a reported home-screen host to include metrics.
Metrics stay in process memory, are discarded with the ready session generation, and are not
restored from the connection cache on cold start. A small widget or one without room at its
current font scale remains connection-only. The Quick Settings tile and service notification
(including actions, permission fallback and promotion policy) are unchanged.

The bridge coalesces metric updates to one every 15 seconds per ready session and requests an
explicit Glance refresh; connection boundaries are not throttled. The RX rate decays while the
process runs; a battery reading expires after 15 minutes without a new reading. Neither a timer,
an alarm nor a new connection owner wakes a suspended app. The launcher can retain its last
rendered view until Android runs the app again; live background refresh is not guaranteed.

`WidgetRadioStatusTest` exercises fake firmware, real-session RX ingestion/decay, Room unread
updates, reconnection, radio switches and expiry. `WidgetPlatformTest` checks localization,
size/font fallback, host redaction, process-only metrics, and the measured placement and wrapping
of real RemoteViews at 220 dp. Physical
radio, locker/launcher behavior and TalkBack on a device require separate verification.
