# WP-403 deviations

## Native platform adaptation

The frozen `MC1RadioControl` runs outside the iOS app and only opens MeshCore One because that
widget process has no radio access. Android supplies two optional surfaces:

- the Glance widget remains a redacted status glance; tapping its body opens the app, while its
  explicit **Connect** action requests the process connection owner;
- the Quick Settings tile is an explicit system user action and requests the same owner.

Neither component constructs a transport, `ConnectionManager`, session container, service graph or
foreground service. `MeshCoreApplication` installs the process bridge before asynchronous
`AppContainer` construction, and the bridge waits for that existing owner with a bounded timeout.
Repeated widget/tile taps are serialized; an already active owner is not asked to reconnect.

## Storage and privacy

The widget cache contains only connection phase, saved-device availability, reconnecting and
permission-needed booleans. It contains no radio name, public key, address, message, room, channel
or contact data. Credential-protected cache reads/writes are suppressed before first unlock, where
the system surfaces show a disconnected, content-free state.

Glance receives one generated `64 x 64` ARGB bitmap per render (16 KiB maximum). The tile uses a
vector resource. No image, identity or message cache was added.

## Platform behavior

API 31-37 use the same typed request/status contract. API 34+ uses the `PendingIntent` Quick
Settings launch API; API 31-33 uses the only platform overload available there. Permission,
pre-unlock, owner-startup timeout, background refusal and no-saved-radio outcomes remain typed and
open the app only where user recovery is required. Optional widget/tile failures do not gate mesh
messaging, persistence or navigation.

## Unverified gates

No physical radio, launcher, OEM background-policy, emulator, iOS, screenshot or accessibility
service run is claimed. JVM/Robolectric tests cover registration, API-range policy, redaction,
pre-unlock, permission/background outcomes, reconnect serialization and bitmap bounds.
