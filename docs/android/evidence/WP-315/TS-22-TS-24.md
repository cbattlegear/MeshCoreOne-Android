## Independent numerical expectations

Expected numbers are fixed constants, not read from Kotlin output, another call
to `RFCalculator`, the App adapter, the terrain renderer or its helpers.
They were characterized separately with Python 3.12.4 standard-library arithmetic
before running the candidate. The asymmetric control uses 50-digit Decimal
arithmetic. These are analytical model expectations, not measured reception,
executed Swift results or bit-exact Darwin claims. Absolute tolerance is
0.000001 in the field's units; it comfortably covers rounding but discriminates
wrong heights, MHz/kHz conversion, segment origins, refraction and field mapping.

For flat terrain, independently evaluate line height above ground
`a + (b-a)*x/L` and subtract spherical-earth sag `x*(L-x)/(2*k*6371000)`.
Divide that gap by `sqrt((299792458/(906*1000000))*x*(L-x)/L)` for clearance.
Evaluate at the specified sample positions, not an unsampled continuous minimum.
Distances for geographic samples use a spherical central angle of radius 6371000 m;
the original on-path fixture already specifies its distances explicitly.
Path loss is `20*log10(L*906)-27.55`; knife-edge loss uses the independently
evaluated ITU-R P.526 expression with `v = -gap*sqrt(2)/radius`.
No such equations are added to candidate test code.
