The coordinator chose a source-equivalent single clear-all action under the
user's autonomy delegation. It is not a direct user selection. The Points
section exposes the existing localized Clear action when selection or analysis
state is present, keeps the existing individual endpoint/repeater clear
controls, and hides the global action while relocation is active (where the
existing Cancel action remains available). The action calls the existing
`LineOfSightStateHolder.clear()` behavior; it does not delete the persisted
repeater/contact list.

`LineOfSightMountedWorkflowTest` mounts the production LOS panel with the real
state holder and deterministic elevation/RF test ports. The visible action
retains the existing localized `Clear` copy and exposes a distinct localized
`Clear All` accessibility label. The test verifies the action is visible and
invokable with a completed relay result, clears both endpoints, repeater and
analysis output while retaining saved repeater contacts, and cancels a profile
fetch already in progress so it cannot publish a stale result.

TS-21 is not accepted by this candidate. `LineOfSightStateHolder` supports a
preselected contact, but `LineOfSightEntry` has no input for it and the current
App navigation caller does not forward one. The caller/navigation paths are
inside held PR #495 (`NativeNavigationShell.kt` and navigation state files);
this candidate does not edit them.

TS-23 has no production delta in this slice. The mounted LOS consumer receives
`LineOfSightState.terrainChartInput`; the live chart's coordinate space and
layout are built from the same `ChartCoordinateSpace` helper covered by its
existing tests. No duplicate presentation calculation was added.
