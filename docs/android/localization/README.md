# WP-005 localization conversion

`tools/android-port/l10n_convert.py` converts the immutable
`db14559b39d32322b06477c6ae676112f583db50` app/widget resources and
`AppShortcuts.xcstrings`. It uses Python's standard library only. The application
translation copy remains GPLv3; the existing app GPLv3 and MeshCore MIT notices
are unchanged. This is resource/format infrastructure, not messaging translation
(removed from active scope, not a future build requirement), widget/shortcut execution (WP-403/404)
or the WP-407 system UX audit.

## Coverage and locale policy

All 120 `.strings`, 48 `.stringsdict` and one `.xcstrings` input are parsed.
The pinned sources contain 2,406 distinct app/widget/shortcut keys. The exact
32 StoreKit/tip/entitlement exclusions leave **2,374 canonical resources**:
2,363 strings and 11 plurals. There are no unsupported or unmapped inputs.
Flat `.strings` plural fallbacks remain separately traceable; a matching
`.stringsdict` overrides them, just as the source runtime does.

Portuguese is the Portugal copy identified by `TRANSLATIONS.md`. Language-wide
`values-pt` intentionally retains the Apple `pt.lproj` fallback for Brazilian
Portuguese, while the per-app choice explicitly says `pt-PT`. Number and plural
rules use the actual requested configuration locale, including `pt-BR`.
Chinese explicitly uses the Simplified script, not generic `zh`.

Every app/widget key has a translation in every source locale. Exactly **seven
Italian shortcut phrases are absent** from the pinned xcstrings catalog; they
are omitted from Italian output and resolve through English, not invented copy.
Exactly those seven English declarations carry a per-resource
`tools:ignore="MissingTranslation"` for the deliberately absent source locale;
a regression requires the marked set to equal the actual missing-key set.
There is no global lint disable/baseline or invented Italian translation.
An existing translation equal to English is not counted as missing.
The key map records all effective sources, quantities, signatures and fallbacks.
Locale records index its complete input array; the explicit record schema describes
optional fields. This avoids repeating paths/blob metadata thousands of times
without losing provenance or introducing implicit English fallback.

## Reproducible commands

From the repository root:

```
python tools/android-port/l10n_convert.py --write --self-test
python tools/android-port/l10n_convert.py --check --self-test

# from android/ (gradlew.bat on Windows)
./gradlew --dependency-verification strict :core:l10n:assembleDebug
./gradlew --dependency-verification strict :core:l10n:testDebugUnitTest :core:l10n:verifyL10nTests
./gradlew --dependency-verification strict :core:l10n:lintDebug
```

`--check` is the default. It compares every declared generated byte, the key
map, generator/configuration hashes and source revisions; missing, modified or
extra generated outputs fail. It never regenerates Swift or Android outputs.
Self-test temporary fixtures are confined to ignored `core/l10n/build/`.
Generation is deterministic; generated XML/Kotlin/oracles must not be hand-edited.

`preBuild` runs `--check --self-test`, so assembly, tests and CI fail on drift.
The module extends the existing `verifyScaffoldTests` aggregate with
`verifyL10nTests`, which requires the four nonempty localization JUnit suites,
minimum family counts, the two original test methods, and no failure/error/skip.
The original four scaffold suites are not counted as localization coverage.
After Gradle, `android-ci` runs `l10n_convert.py --check --verify-android-tests` on the module's JUnit results to
prove the localization suites were discovered and passed.

### Test-result check

```
python tools/android-port/l10n_convert.py --check \
  --verify-android-tests android/core/l10n/build/test-results/testDebugUnitTest
```

Missing, malformed, zero-test, failed, skipped, duplicate, incomplete or stale reports fail the check. It never
executes report contents or writes into the read-only Swift tree. `--copy-android-junit <dir>` additionally copies the
validated raw XML plus a `summary.json` into a new absolute directory; CI does not use it.

The module owns its dependency lock in
`android/core/l10n/gradle/dependency-locks/core-l10n.lockfile`; all versions and
test aliases come from the existing pinned conventions/catalog. Initial lock
creation must exercise actual assembly as well as dependency resolution because
AGP's empty `androidApis` state is only resolved by an Android build. Checksum
admission remains the shared owner's responsibility, never verification-off.

## Parser and format contract

OpenStep strings are lexed character by character: quoted keys/values, comments,
semicolons inside values, escaped quotes/backslashes/apostrophes, octal/Unicode
escapes, UTF8/UTF16 BOMs, actual newlines and multiline continuations. Duplicate
keys, malformed/unsupported constructs, unpaired surrogates and invalid XML fail
with source/key diagnostics. Safe XML plist parsing rejects entities/custom DTDs
and duplicate keys. Xcstrings supports the actual translated `stringUnit` schema;
unknown locales, variations/substitutions or dropped named parameters fail.

Names are deterministic `l10n_<domain>_<table>_<original-key-slug>`, with separate
`app`, `widget` and `shortcut` namespaces. Dots/punctuation do not get a
collision-hiding suffix: colliding Android or Kotlin names fail. Existing names
are independent of enumeration order and future added keys.

The explicit supported printf mapping is `%@` to string, `%d`/`%i` to signed
`Int`, `%ld`/`%lld` to signed `Long`, and finite fixed-precision `%f` to `Double`.
Arguments become numbered Android/Java directives, preserving reordering,
repeated arguments, supported padding and widths. Unsupported/lossy directives
(including general/exponential floats, C pointers/strings, dynamic precision
and integer precision) fail; none occur in these pinned inputs. No blanket
regex substitution or default-locale formatting is used.

Literal `%%` is collapsed for nonformatted resources (for example **Airtime %**)
but remains formatter-escaped when arguments exist. Quotes, XML characters,
leading `@`/`?`, apostrophes, whitespace and newlines survive AAPT compilation.
The Chinese airtime label intentionally contains no percent character in the
source; it remains unchanged rather than being retranslated.

Plural quantity arguments are distinct from displayed arguments: the partial
node-removal plural selects on argument **2** (total), not argument 1 (removed).
Each source `one/few/many/other` form is retained, including Slavic families and
single-category Korean/Chinese. Zero/two dictionaries are additionally parser
fixtures, not claimed source categories. Android's CLDR French-zero and
Portuguese-variant behavior is explicitly tested rather than using the
oversimplified zero rule in the read-only translation guide.

Android's quantity API accepts only `Int`; source/widget counts can be `Long`.
For large counts the helper selects with a representative retaining the twelve
locales' modulo-10/100/1,000,000 category behavior above one million. It never
narrows or clamps the displayed number, including `Long.MIN_VALUE/MAX_VALUE`.
Selection uses magnitude for signed counts; `Int.MIN_VALUE` is represented
safely instead of feeding Android's overflowing native absolute-value path.
The displayed value remains signed and unchanged.

## Consumers and native declarations

### WP-308 recovered-draft copy contract

`values/wp308_recovery.xml` is a handwritten WP-005-owned Android-only resource
slice for the separate, copy-only recovery list. It is not generated from the
pinned Swift catalog and does not change any original message text or existing
localized wording. Each new declaration deliberately falls back to English
with its own `MissingTranslation` annotation; no source translation exists and
none is invented. These remain translatable resources, not English literals in
the feature.

The committed consumer at `14b71be599ff44022eae62f39a9f43f4deab2508`
accepts seven `RecoveredDraftLabels` fields. Wrap the following shared
`com.meshcoreone.android.core.l10n.R.string` IDs in the existing `UiText`
resource type; this change does not add a feature dependency or wire a route.

| Consumer field | Shared resource ID |
| --- | --- |
| title | `wp308_recovery_title` |
| explanation | `wp308_recovery_explanation` |
| empty | `wp308_recovery_empty` |
| refresh | `wp308_recovery_refresh` |
| loadMore | `wp308_recovery_load_more` |
| chooseChat | `wp308_recovery_choose_chat` |
| copyToSelectedChat | `wp308_recovery_copy_to_selected_chat` |

Callback-owned status/failure/feedback IDs use the same `wp308_recovery_`
prefix: `status_unknown_origin`, `status_replaced_occupant`,
`status_delivery_unknown`, `load_failed`, `copy_failed`,
`destination_conflict` and `copied`. Origin status does not establish delivery
state. Use `status_delivery_unknown` only for an actually uncertain state;
do not replace known delivery evidence with uncertainty. Use
`destination_conflict` only when the destination owner confirms a nonempty
draft was not overwritten. Use `copied` only after actual copy completion,
never when a request merely starts or its outcome is uncertain.
The generic copy failure asks the user to check the destination rather than
asserting nothing changed. Visible action names also provide meaningful
accessibility labels without a second, divergent set of copy.

`RecoveredDraftResourceTest` adds two compiled-resource controls: all fourteen
IDs retain exact copy across the twelve supported locales plus Portuguese
regional, RTL and unsupported-locale fallback, and copy-only/uncertain-delivery
wording remains explicit. These are resource assertions, not UI integration,
TalkBack, 200% font, disk-reopen, delivery or device acceptance.

### Generated source declarations

Use `com.meshcoreone.android.core.l10n.generated.App*Strings`,
`WidgetLocalizableStrings` and `ShortcutAppShortcutsStrings`. Plain members are
shared resource IDs; formatted/plural members are typed functions accepting the
current `Resources` and `String`/`Int`/`Long`/`Double` arguments. Use those functions
for `Long` plurals rather than narrowing through `pluralStringResource`.
Materialize source-style object descriptions before passing string arguments.
Do not cache resources across per-app language changes or invent independent
UI keys/copy.

```kotlin
val title = resources.getString(AppLocalizableStrings.tabsChats)
val count = WidgetLocalizableStrings.lldUnreadMessages(resources, unreadCount)
val partial = AppSettingsStrings.dangerZoneAlertRemoveUnfavoritedPartial(
    resources, removedCount, totalCount,
)
```

`RegionalSubdivisionNames` preserves the 59-code localized lookup and genuine
unknown-code `null` contract, not the wider geographic/radio preset behavior.
The mounted onboarding consumer is already connected by WP-211's merged
[regional-label repair](https://github.com/cbattlegear/MeshCoreOne-Android/pull/348).
`AndroidAppContainerFactory` supplies current `AppLanguages` resources through
`AppOnboarding` to `ServicesRegionCatalog`, which injects this generated lookup
into the JVM regional resolver. `RegionStepScreen` uses that catalog for picker
entries, the selected subdivision row and the detected-region heading. The
resource provider is evaluated on demand, including API31/32 app-language
changes; the core service remains Android-free.

The subdivision entry in [`cases.json`](cases.json) binds the original
59-code/12-locale resource family to those production paths, the app-language
adapter regressions and the French/German mounted-picker methods running in
the App suite. Independent expected visible names, country-switch clearing and
the committed `AU-NT` identity are asserted without applying a radio preset or
completing onboarding. This closes issue #374's missing consumer correspondence,
not universal all-locale UI or full-WP acceptance. The map is traceability, not
an execution result; exact-candidate hosted logs remain authoritative.

`resources.properties` declares English fallback and the owned
`@xml/l10n_locales` declares all twelve per-app language choices. Actual AGP9.4
app-merger/APK inspection proved that `android:localeConfig` is rejected from
library manifests. The coordinator then granted the exact application-manifest
path for this one attribute, which is now on the existing `<application>`:

```xml
android:localeConfig="@xml/l10n_locales"
```

Pinned AAPT37.0.0 inspection of the actual built APK verifies that the manifest
reference resolves to the packaged XML, all twelve tags are present, and the
localized string table has all twelve source variants. This is static APK proof,
not physical Settings UI. No application ID/SDK/permission/UI change is made.
The five old scaffold tab IDs have generated
localized aliases to canonical keys. All original English scaffold keys/copy
remain; incomplete-build explanations are explicitly English-only, not fabricated
translations or completed-feature copy.

## Bounded source correction and evidence

[`format-adaptations.json`](format-adaptations.json) contains exactly one
coordinator-authorized output correction:
`Contacts/contacts.results.comparison/zh-Hans`, argument1 `%@` to numeric `%d`.
The pinned English signature and actual `Int` producer/consumer establish the
contract. Original copy, blob SHA, value SHA256 and expected Android replacement
are checked and recorded. Any changed fingerprint/signature/replacement fails;
all other inconsistencies still fail. Swift and surrounding Chinese copy remain
read-only. This is not a general permission to fix translations.

[`exclusions.json`](exclusions.json) lists every exact billing exclusion and
reason. Theme names, generic theme-application copy, support links, all-themes-
unlocked text, user-facing network errors and backup restore remain included.
Service/domain logs are not scraped or localized by this resource pipeline.
